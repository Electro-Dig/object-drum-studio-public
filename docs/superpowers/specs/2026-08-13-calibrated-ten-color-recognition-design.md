# 十色标定识别与独立测试节点设计

日期：2026-08-13
状态：已由用户批准推荐方向，进入实现
分支：`feature/lab-recognition-v1`

## 目标

把现场控制台从“HSV 阈值同时负责找物件和判颜色”重构为三层识别：

1. 空场背景差分回答“哪里出现了物件”；
2. Lab 原型分类回答“物件属于哪一种颜色”；
3. 几何轨迹与多帧投票回答“是不是同一个新进入的物件”。

默认提供照片中十个圆木片对应的 10 个颜色/声音槽，继续支持同色随机模式。多个新物件可同时触发并让声音重叠；每个物件每次进入画面只触发一次，离开后再次进入可重新触发。

## 不在第一版范围内

- 不训练神经网络，不引入远程推理或后端服务。
- 不使用 ArUco、AprilTag 等可见编码标记。
- 不处理完全动态的摄像机、持续抖动的背景或严重重叠遮挡。
- 不覆盖或重新部署旧站点 `object-drum-client-show-console-v1.netlify.app`。

## 数据流

```text
摄像头帧
  -> 空场 Lab 背景差分
  -> 形态学去噪与连通域
  -> 组件内部稳健 Lab 取色
  -> 十色原型最近距离 + 未知色拒识
  -> PadTracker 仅按几何保持 ID
  -> 轨迹内 3/5 帧颜色投票并锁定
  -> EntryGate 只接收已锁定的新轨迹
  -> Web Audio 并发播放
```

## 模块边界

### `src/detection/colorMetrics.js`

纯函数模块：

- `rgbToLab(r, g, b)`：sRGB 转 CIELAB。
- `hexToLab(hex)`：把槽位默认色或手动色转换为原型。
- `colorDistance(a, b)`：第一版使用 ΔE76，保留替换 ΔE00 的接口边界。
- `classifyColor(lab, prototypes, options)`：比较全部原型，返回最佳类别、距离、冠亚差距和置信度；距离过大或差距不足时返回 `null`，不得受原型数组顺序影响。

相机颜色不是色度计测量值，因此这里的 ΔE 是工程特征距离，不宣称为严格色差测量。

### `src/detection/calibratedColorDetector.js`

帧级纯输入/输出模块：

- `createBackgroundModel(rgba, width, height)`：把空场帧预转换为 Lab 背景模型。
- `detectCalibratedObjects(...)`：对当前帧做 Lab 背景差分、3×3 开/闭运算、8 邻域连通域、面积过滤、组件内部中位 Lab、原型分类。

输出保持现有 pad 形状：`instrument/ruleId/label/area/bounds/centroid/color/outline`，并增加分类距离、差距和置信度诊断。这样音频、绘制和 `EntryGate` 不需要理解检测器内部细节。

若没有空场模型，控制台使用现有 HSV 检测器作为回退；一旦捕捉空场，默认切换到新检测器。

### `src/detection/padTracker.js`

增加 `strictRuleMatch` 选项：

- 默认 `true`，保持旧 Studio 行为；
- Console 使用 `false`，颜色变化仅是匹配惩罚，不再是创建新轨迹的硬条件。

### `src/detection/trackColorResolver.js`

按稳定 track ID 累计最近 5 帧颜色证据：

- 至少 3 帧同类才确认；
- 确认后单帧跳色不翻转；
- 未确认或被拒识的轨迹不交给 `EntryGate`；
- 轨迹超时消失时清理投票状态。

## 配置与迁移

- `CONSOLE_SCHEMA_VERSION` 升至 2。
- 新默认 profile 包含 10 个唯一槽位：粉、宝蓝、红、深青绿、天蓝、深棕、紫、橙、亮黄、荧光绿。
- 接受 v1 配置包并迁移：保留原六槽内容，自动补齐第 7–10 槽；导出统一为 v2。
- 新版使用 v2 localStorage key；首次读取不到时再读取旧 v1 key、迁移并保存到 v2。这样保留已有现场配置，又避免旧页面回写时把十槽截断。
- 固定映射模式升级为 `ten-color`；读取旧 `six-color` 时迁移到 `ten-color`。
- 同色随机模式仍只用第一个启用槽位作为颜色原型，声音从全部启用槽位中随机选择。
- 同色随机 UI 只禁用“首个启用槽”之外的取色按钮，不能按卡片下标判断。

## 操作界面

System 区新增第四项“场景”，并提供“捕捉空场”按钮：

1. 连接摄像头；
2. 清空灰布上的所有物件；
3. 点击“捕捉空场”；
4. 逐色使用现有“镜头取色”标定；
5. 进入演出模式。

换摄像头、移动机位、换布或明显改变灯光时，背景模型立即失效，界面恢复“待校准”。演出模式开始前若未捕捉空场，允许使用 HSV 回退，但界面明确显示“兼容识别”。

## 错误处理与安全边界

- 大面积曝光漂移导致前景比例过高时，不输出物件，返回“背景失配”诊断并提示重新捕捉空场。
- 颜色距离或冠亚差距不满足阈值时拒识，不播放错误声音。
- 触发、上传音效和配置包都继续在浏览器本地运行。
- 新版本部署到全新的 Netlify site ID；旧站点地址和部署记录不修改。
- 更新 Service Worker cache 名称，避免测试设备继续读取旧六槽资源。

## 验收标准

- 默认 profile 有 10 个可独立上传、试听、启用的声音槽。
- 灰背景上的低饱和深棕色可被前景检测并正确分类。
- 蓝/天蓝、红/粉/紫、橙/黄/荧光绿的分类不依赖规则数组顺序。
- 模糊颜色或未知物件被拒识，不触发声音。
- 同一物件单帧跳色不更换 track ID、不重复触发。
- 10 个分离物件同时进入可形成 10 个 entry。
- 没有空场模型时旧 HSV 路径仍能运行。
- 全量 `npm.cmd test` 通过，并完成摄像头页面的桌面/窄屏浏览器检查。
- 发布得到一个全新的 Netlify URL，旧节点保持不变。
